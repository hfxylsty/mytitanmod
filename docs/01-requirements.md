# 01 · 需求与竞品分析

**本文件职责**：定义「我们要做什么、不做什么、为什么」。它给出需求来源、玩法还原清单（逐条标注必做/可选/不做）、竞品对照与差异化空间、功能性与非功能性需求、以及尚不确定的开放问题。**玩法实现的详细设计**归 `03-gameplay-systems.md`，**排期与验收**归 `06-roadmap.md`，本文件只负责「需求是什么」。

**「只取玩法，不取表达」的操作定义**（每条需求都要过这一关）：

- **可以借鉴**：机制、数值设计、系统结构、界面流程、玩家体验目标——这些是「思想」。
- **不可以碰**：源码（含反编译产物）、贴图、音效、模型、语言文件文本、物品中文名与注册名——这些是「表达」。
- **执行细则**：写需求时只引用资料页的**描述句**，不引用任何代码/资源；具体名词一律另起（见 [09-glossary.md](09-glossary.md) §1.4 的「我方不得沿用此名」清单）。

## 2. 玩法还原清单

优先级口径：**M1** = 垂直切片必须端到端跑通（1 泰坦 + 1 召唤物 + 渲染 + 1 武器）；**M2** = 核心玩法（差异化五条的主体）；**M3** = 内容扩展与打磨；**不做** = 明确排除，防止范围蔓延。里程碑正式定义由 [06-roadmap.md](06-roadmap.md) 收口。

### 2.1 生成与成长

| 机制 | 原版描述（一句话） | 是否纳入 | 优先级 | 备注 |
|---|---|---|---|---|
| 自然生成 | 类似结构生成，几率 1/2000~1/25000，数量取决于玩家已加载区块数 | ✅ | M3 | **数值先不照抄**：1/25000 在单人局等于「几乎遇不到」，我们改为可配置 + 更保守的默认值（待平衡）；实现方式（结构式 vs 刷怪事件）待定 |
| 圣骑士转化 | 圣骑士生物接触「空灵平面」的超自然力量后变成泰坦 | ⚠️ 可选 | M3 | 低优先；需要时按「事件触发 + 实体替换」实现，转化过程要有可见反馈 |
| 泰坦之魂附身 | 泰坦之魂主动附身对应的圣骑士生物使其成为泰坦 | ⚠️ 可选 | M3 | 与上一行合并为一个「晋升」系统更省成本；我们这边的对应物已定名**泰坦残响（`titan_echo`）**，见 [10-content-roster.md](10-content-roster.md) |
| 生长血清 | 玩家向生物投放生长血清使其进化为泰坦（唯一玩家可控方式） | ✅ | M1 | **名字禁用**（[07-compliance.md](07-compliance.md) §3.3），改用**催生灵液（`quickening_ichor`）**；因是玩家可控，**它才是我们默认的「开战入口」** |
| 五级召唤物谱系 | 忠诚者攻击主人目标；牧师治疗；狂热者机动突进；主教远程减益；圣骑士飞行+双攻击模式+死亡回馈 | ✅ **必做** | M2 | **差异化目标 1**。五级 AI 各自独立，是本项目最主要的工作量；生成上限默认沿用原模组量级（120/60/30/15/6）并进配置 |
| 重生长 | 血量 <5% 时每 tick 1/1000 几率缩小回普通体型再长大，重置血量并短暂免疫；双泰坦互斗时可连锁触发 | ✅ **必做** | M2 | **差异化目标 2**。要点是「逼玩家打爆发」，所以免疫时长与触发概率必须可调、必须在 HUD 上可观察 |
| 强化原版生物 | 61 种原版生物的泰坦化强化版，均为召唤物 | ⚠️ 部分 | M2/M3 | 只做**召唤物谱系需要的那几种原型**，不做 61 种全量（`00-overview.md` 非目标） |

### 2.2 战斗规则

| 机制 | 原版描述（一句话） | 是否纳入 | 优先级 | 备注 |
|---|---|---|---|---|
| 破防条件 | 泰坦需先被特定方式击晕（射落水晶、特定武器等），未破防几乎免疫外来伤害 | ✅ **必做** | M2 | **差异化目标 3**。垂直切片先用 1 个可判定条件（如「射落 N 个悬浮水晶」），其余泰坦各配一个 |
| 伤害上限 | 单次伤害上限 1000 点，困难模式（原模组称「噩梦模式」）500 点 | ✅ **必做** | M1 | **差异化目标 5**；用 `LivingIncomingDamageEvent#setAmount` 落地（签名已核验） |
| 伤害冷却 | 两次有效伤害之间 1.5 秒冷却 | ✅ **必做** | M1 | 用 `#setInvulnerabilityTicks`；注意与破防状态、重生长免疫的优先级 |
| 无视小额伤害 | 无视 <20 点的攻击伤害 | ✅ **必做** | M1 | 阈值进配置；目的是让「刮痧」无效，逼玩家上泰坦级装备 |
| 免疫列表 | 免疫燃烧、窒息、摔落、虚空等 | ✅ **必做** | M1 | 用原版 `DamageType` 标签实现（`data/titanreborn/tags/damage_type/`），不写逐条 if |
| 1 点击退抗性 | 所有泰坦完全免疫击退 | ✅ | M1 | 属性层 `Attributes.KNOCKBACK_RESISTANCE = 1.0`，零代码成本 |
| 窃魂伤害 | 泰坦攻击附带的特殊伤害：无视护甲、随难度缩放 | ✅ **必做** | M2 | **差异化目标 5**；自定义 `DamageType` + 独立结算通道，与普通伤害分开记日志便于验收 |
| 虚空伤害 | 泰坦攻击附带的另一类特殊伤害 | ✅ | M2 | 与窃魂伤害同批实现 |
| 护甲层级 | 泰坦有自定义护甲档（小型 21 / 普通 22 / 大型 23 / 神 24） | ✅ | M2 | 用**自定义属性**表达，不与原版 `Attributes.ARMOR` 混用，避免和其他模组的护甲计算打架 |
| 攻击节奏 | 默认每 1.5 秒攻击一次，比普通怪物略慢 | ✅ | M1 | 作为设计基线；「巨型但慢」是玩家可读的节奏信号 |
| 仇恨连锁 | 类似僵尸猪人的仇恨传播机制 | ✅ | M2 | 广播半径、传播上限进配置，防止大规模连锁引发卡顿 |
| 区块刷新重置 | 泰坦因区块刷新而重置血量与仇恨；玩家退出重进同样重置 | ✅ | M2 | **性能与存档双重考虑**：巨型实体长期驻留会持续吃 tick 并撑大存档 |
| 泰坦破坏方块 | 有专属破坏方式，飞溅方块落地产生小爆炸并伤害周围生物，无视 `mobGriefing` | ⚠️ 可选 | M3 | 默认**遵守** `mobGriefing`（与竞品一致、对服务器友好），另给一个「无视」开关给硬核玩法 |
| 创造模式 / 作弊特判 | 泰坦会对创造模式玩家还击；玩家作弊（免疫伤害）会被踢出服务器 | ⚠️ 部分 | M3 | 只保留「创造模式可被攻击、泰坦会还击」；**踢人逻辑不做**（服务器管理不该由模组越权执行），改为可配置的日志告警 |
| 双模式 | 普通模式 / 困难模式（原模组称「噩梦模式」，改伤害上限与泰坦行为） | ✅ **必做** | M3 | **差异化目标 4**；**模式名必须另起**（[07-compliance.md](07-compliance.md) §3.3 把「噩梦模式/灭神模式」列为禁用名）——命名未定前文档一律写「困难模式（暂名）」。模式切换现方案是**跟随原版难度**：普通难度=普通模式，困难难度=困难模式（[03-gameplay-systems.md](03-gameplay-systems.md) §2.6）；若改成独立开关，必须同步改那份文档 |
| 两个维度 | 新增两个维度用于终局 BOSS 战 | ⚠️ 可选 | M3 | 数据驱动（`data/titanreborn/dimension/` + `dimension_type/`）；**待验证**字段集；优先做 1 个 |
| 矿石装备体系 | 新矿石 + 对应装备工具武器用于对抗泰坦 | ⚠️ 可选 | M3 | 装备是「破防钥匙」的载体，不做独立数值膨胀；配方/战利品全部数据驱动 |
| 把目标血量减半等极端规则 | 对血量超 10 亿的目标每次攻击移除其一半血量 | ❌ | 不做 | 针对特定整合包的极端数值，与本项目无关 |

### 2.3 明确不做（范围防线）

| 不做 | 原因 |
|---|---|
| 复刻 19 泰坦 / 222 物品 / 61 强化生物 | `00-overview.md` 非目标；我们做机制差异化 |
| 反编译任何原模组 jar、读 `.tmp/titans-src` 与 `.tmp/mac-src` 的 `.java` | 合规红线；细则与「原仓库只允许用于核对内容清单与避重名」的操作定义见 [07-compliance.md](07-compliance.md) §4 |
| 沿用禁用名清单里的任何名称 | [07-compliance.md](07-compliance.md) §3.3（武器/道具/生物/地名/模式五类，含「生长血清」「噩梦模式/灭神模式」这类看似通用的词） |
| 「大乱斗版本」式发行变体 | 发行策略问题，不是机制 |
| 清除玩家手持物品 NBT、逐条针对其它模组的特判 | 侵入性强、与其他模组天然冲突，性价比极低 |
| 打破第四面墙的梗与特定玩家名特判 | 属原作者的表达与玩笑，不借鉴 |
| 创造模式玩家踢出服务器 | 越权；改为日志/可配置告警 |
| 1.21.1 以外的版本、Fabric/Forge 双端、数据包形态 | `00-overview.md` 非目标 |

| 它做了什么 | 它没做什么 | 我们的差异化空间 |

| 有 `worldgen` 标签、自称加矿石与装备（"more equipment, tools, and ores"），但自述「部分 BOSS 阶段装备尚未实现」 | 无公开源码 → 社区无法审计、无法适配、无法打补丁 | 开放、可读、可配置；用自建美术与自研代码形成合法且可维护的护城河 |

**竞品分析的三条结论**：

1. **版本位是我们的第一层差异**：两个 1.21.x 竞品分别在 1.21.4 与 1.21.1，前者体量 93 万下载但版本不对，后者同版本但机制在「还原数量」上。我们选 1.21.1 + 机制深度，是**唯一还没被占满的组合**。
2. **机制空位是第二层差异**：竞品的自述里，「召唤物五级谱系 / 重生长 / 破防 / 双模式 / 完整伤害规则」这五条**没有一条被明确提及**——这正是 `00-overview.md` 3.1 的五条差异化目标，不是拍脑袋定的。
3. **净室是我们的第三层差异（也是法律护城河）**：主流竞品全是 ARR 且无源码；我们是自建代码 + 自建美术 + 开放可维护。代价是不能抄任何东西，收益是**我们不会因为上游消失或被下架而失去项目**。

## 4. 功能性需求

每条给「一句可验收的描述」——验收 = 有客观观察点（日志、GameTest、可视化状态），不写「体验良好」这类无法判定的词。

### 4.1 实体与 BOSS 战

1. 注册至少 1 个泰坦实体类型（`Registries.ENTITY_TYPE`），能用 `/summon titanreborn:<name>` 生成，且生成后可见、会移动、有碰撞体积。
2. 泰坦有独立属性表（含自定义护甲属性与 `KNOCKBACK_RESISTANCE = 1.0`），通过 `EntityAttributeCreationEvent` 挂载，`/attribute` 可读出全部数值。
3. 单次有效伤害被上限规则截断：对泰坦施加 5000 点伤害后，一次结算的血量下降不超过配置上限（默认 1000）；处于困难模式（暂名）时上限变为配置值（默认 500）。
4. 两次有效伤害之间有 1.5 秒（可配置）冷却，冷却期间再次命中不扣血且日志记录一次「冷却拦截」。
5. 小于 20 点（可配置）的攻击伤害被完全忽略，日志记录「小额伤害拦截」。
6. 泰坦免疫燃烧、窒息、摔落、虚空四类伤害：把泰坦置于岩浆/水中/高处坠落/虚空边上，血量不下降（GameTest 内可用伤害源直接注入验证）。
7. 泰坦不会因和平难度或区块卸载而消失（区块卸载后重新加载仍存在，符合 §2.2「区块刷新重置」的重置语义）。
8. 破防状态是显式、可观察的状态：未破防时伤害被拒（日志+状态标记），破防后同样一击造成伤害；破防有持续时间与回复机制。

### 4.2 召唤物

1. 五级召唤物各有独立实体类型与独立 AI，能从泰坦身上生成、服从「攻击主人的目标」这一基本契约。
2. 每级召唤物有独立生成上限配置（默认 120/60/30/15/6），达到上限时停止生成且日志记录一次「上限拦截」。
3. 领主死亡时（若附近存在对应泰坦）触发回馈事件：治愈该泰坦固定百分比并可被观察。
4. 召唤物在泰坦死亡后进入「失控」状态（可配置为消散或保留），不遗留永久敌对实体。

### 4.3 世界生成

1. 泰坦自然生成开关默认可用，生成权重/几率来自配置文件；关闭后世界中不再自动出现泰坦。
2. 生成遵循「玩家已加载区块数」语义，单次生成尝试不对服务器造成 >X ms 的 tick 阻塞（X 在 §5 给定）。
3. 泰坦只在允许的维度与生物群系标签内生成（标签可用数据包覆写）。
4. 催生灵液（`quickening_ichor`）可把指定生物转化为对应泰坦，转化过程有可见反馈且产出的泰坦带有「由转化产生」标记。

### 4.4 物品与装备

1. 至少 1 件泰坦级武器可在垂直切片中走完「获得→装备→对泰坦造成伤害」链路。
2. 武器/装备的数值以 `Item.Properties()` + 数据组件表达，不写死在 NBT 字符串里。
3. 全部配方、战利品表、标签为 JSON（`data/titanreborn/`），删除对应 JSON 后游戏仍能正常启动（内容消失而非崩溃）。
4. 每件泰坦级物品有 `en_us.json` 与 `zh_cn.json` 语言键，键名不含原模组任何名称。

### 4.5 维度

1. （若纳入）新增维度可通过 `/execute in titanreborn:<dim>` 进入，退出后玩家位置与物品栏完好。
2. 维度定义完全数据驱动（`dimension/` + `dimension_type/`），不改动原版维度文件。
3. 维度内泰坦生成规则与主世界分离，可独立开关。

### 4.6 客户端表现

1. 泰坦渲染器通过 `EntityRenderersEvent.RegisterRenderers` 注册，进游戏可见正确模型（未加载时不得出现黑紫方块/隐形实体）。
2. 模型/动画资源缺失时降级为可辨识的占位渲染 + 一条明确日志，不崩溃。
3. 泰坦的关键战斗状态（破防中 / 重生长中 / 冷却中）在客户端有可区分的视觉反馈。
4. 客户端不参与任何伤害结算：断连或客户端改包不会改变服务端血量结果。

### 4.7 多人兼容

1. 所有伤害与状态判定在服务端权威执行；用两台客户端接入专用服务器复测，双方看到的血量与破防状态一致。
2. 自定义同步只走 `CustomPacketPayload`（`RegisterPayloadHandlersEvent` 注册），且单包体积远低于 32 KiB（发往服务端）/ 1 MiB（发往客户端）限额。
3. 服务器未装本模组时客户端不得因缺失 payload 而崩溃（要么拒绝连接并给出可读提示，要么完全不依赖）。

### 4.8 配置项

1. 全部数值型规则（伤害上限、冷却、小额阈值、免疫列表、各召唤物上限、重生长概率与免疫时长、自然生成几率、仇恨连锁半径、`mobGriefing` 覆盖开关）都可在配置文件中修改，且改动在重启后生效。
2. 配置加载失败（字段缺失/类型错误）时使用默认值并输出警告日志，不阻止游戏启动。

### 4.9 指令

1. 提供管理指令（如 `/<modid> titan list|spawn|state|mode`），普通玩家无权限、OP 可用。
2. 指令能改变泰坦的调试状态（如强制破防、强制重生长、打印当前规则命中计数），供验收与排错使用。
3. 指令在专用服务器上可用，且不依赖客户端侧代码。

## 5. 非功能性需求

### 5.1 性能（**设计目标，量级估算，待实测校准**）

| 指标 | 目标 | 依据 / 测法 |
|---|---|---|
| 服务端 tick | 最坏场景（1 泰坦 + 100 召唤物同屏）**MSPT ≤ 50**（≥20 TPS） | `debug` 采样 + 自建计数器；最坏场景由 §4.2 上限配置构造 |
| 单泰坦 tick 成本 | ≤ **0.15 ms** | 同上，取 60 s 平均 |
| 召唤物总 tick 成本 | 100 只合计 ≤ **1.5 ms/tick** | 诱导「AI 降频」设计：远处召唤物按 2~4 tick 步进 |
| 伤害结算 | 单次结算 ≤ **0.05 ms** | 伤害事件内不做搜索/遍历，规则查表 |
| 客户端帧率 | 20 泰坦 + 100 召唤物场景 ≥ **60 FPS**（中端独显、视距 12） | 手工采样；多部件渲染必须做视锥剔除与远处降级 |
| 生成开销 | 单次生成尝试 tick 阻塞 ≤ **1 ms** | 生成用「错峰调度」，不在同一 tick 内批量生成召唤物 |
| 网络同步 | 每实体每秒同步包 ≤ **10**，仅同步状态变化 | payload 计数打点 + 抓包核对 |

**设计取向**：巨型实体 + 海量召唤物的最大风险是「每 tick 全量搜索」。因此硬性要求——仇恨/目标搜索一律走**节流 + 空间网格**，禁用 `getEntitiesOfClass` 的全量扫描式写法；召唤物生成与 AI 更新必须错峰。

### 5.2 兼容性

1. **不破坏原版存档**：新增内容全部在 `titanreborn` 命名空间；卸载模组后存档可加载（仅丢失本模组内容，不损坏区块与玩家数据）。验收：装→玩→卸→再进存档。
2. **不覆盖原版注册项**：不替换原版血条/护甲条（与竞品选择相反），不改原版实体属性；需要额外显示时走自带 HUD 且默认关闭。
3. **与其他模组共存策略**：
   - 优先用 NeoForge 事件与属性系统；**Mixin 默认禁用**，仅兼容性补丁可用且必须写明理由；
   - 伤害结算不假设「只有原版伤害源」，对未知 `DamageType` 默认可被打断（可配置）；
   - 对其它模组的装备不做「瞬间摧毁」式硬编码特判（`PORT-PLAN.md` 拦路虎 2 的教训：强耦合 = 无法跨版本）。
4. **版本承诺**：只支持 1.21.1 + NeoForge 21.1.x；其它版本明确不支持、不猜测（当前验证工程 NeoForge 21.1.252，见 [example-mod/build.gradle](<../example-mod/build.gradle>)）。
5. **已知环境限制**：本机 `gradlew build` 因沙箱完整性级别问题会让 NeoForm 的 `recompile` 失败（详见 `E:\titanmod\.tmp\research\REPORT-neoforge-recompile-failure.md`）。因此**里程碑验收不能只依赖本机 build 结果**，必须同时保留「在沙箱外 Medium IL 的 JDK 21 上可复现」的验收路径。

### 5.3 可测试性（GameTest 覆盖范围）

用 `@GameTestHolder("titanreborn")` + `@GameTest`（模板放 `data/titanreborn/structure/`，[官方口径](https://docs.neoforged.net/docs/1.21.1/misc/gametest/)），必须覆盖：

| 测试 | 断言要点 |
|---|---|
| 伤害上限 | 注入远超上限的伤害，血量下降 == 配置上限 |
| 伤害冷却 | 连击两次，第二次不扣血；推进 tick 超过冷却后第三次扣血 |
| 小额伤害免疫 | 注入 <20 点伤害，血量不变 |
| 免疫列表 | 逐类注入燃烧/窒息/摔落/虚空伤害，血量均不变 |
| 破防开关 | 未破防注入伤害 → 无变化；破防后同伤害 → 生效 |
| 重生长 | 把血量置到阈值下，推进 tick 至触发，断言：体型/缩放变化 + 血量回到满 + 免疫窗口内伤害无效 |
| 召唤物上限 | 反复触发召唤，断言实体总数不超过配置上限 |
| 跨区块重置 | 卸载并重载区块，断言血量与仇恨被重置而非保留 |
| 数据缺失降级 | 删除一个配方 JSON 后启动，断言游戏可启动且该配方不可用 |
| 存档往返 | 保存→加载存档，断言泰坦的破防状态与自定义属性（如护甲层级）正确恢复 |

### 5.4 可维护性

1. **数据驱动优先**：物品、方块、装备、配方、战利品、标签、维度、生物群系一律 JSON（`data/titanreborn/`）；Java 只写逻辑，不写内容表。
2. **单一数值出口**：同一数值（伤害上限、冷却、上限数）只允许在一个配置类里定义，禁止散落硬编码。
3. **一个机制一个类**：伤害规则、破防、重生长、召唤物生成各为独立可单测的组件，不塞进巨型实体类。
4. **文档同步**：机制改动必须同步 [03-gameplay-systems.md](03-gameplay-systems.md) 与本文件对应行；新增术语先补 [09-glossary.md](09-glossary.md)。
5. **可复现构建**：一条命令完成构建，不依赖手工步骤（`00-overview.md` 3.2）。
