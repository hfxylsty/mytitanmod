# 07 · 净室纪律与合规边界

> 本文件职责：定义**什么能碰、什么不能碰**，以及怎么证明我们没碰。
> 这是本项目的红线文件。**任何与其他文档冲突的表述，以本文件为准。**

## 一、前提事实（已核实）

| 事实 | 依据 |
|---|---|
| `Mrbt0907/The-Titans-Mod` 仓库**没有 LICENSE 文件** | 探测 `LICENSE`、`LICENSE.txt`、`LICENSE.md`、`COPYING` 全部 404 |
| `Mrbt0907/Minecraft-Adventures-Core`（MrbtUtil）**也没有 LICENSE** | 同上方法探测 |
| 无 LICENSE ⇒ 默认 **保留所有权利（All Rights Reserved）** | 著作权法默认规则；中文资料页亦注明"闭源模组" |
| 发行版内容量远超公开源码（19 泰坦 / 85 实体 vs 仓库 10 实体） | 见 [PORT-PLAN.md](PORT-PLAN.md) 第二节 |

**结论：未经作者书面许可，不得复制其代码、素材，也不得分发衍生品。**

## 二、三条路线与我们的选择

| 路线 | 合规性 | 我们的决定 |
|---|---|---|
| 迁移/改写原仓库代码 | ❌ 侵权（无授权） | **不做** |
| 反编译发行版 jar | ❌❌ 侵权 + 违反 EULA 精神 | **不做** |
| **净室重实现**（只借鉴玩法，代码素材全自建） | ✅ 可行 | **我们的路线** |

> 说明：**玩法机制、数值规则、系统结构**属于"思想"（idea），通常不受著作权保护；受保护的是
> 具体的**代码表达**与**美术/音频素材**。因此"做个一样玩法的泰坦模组"是可行的，
> "抄它的代码和贴图"不行。本文件后续所有规则都围绕这条界线展开。

## 三、红线清单（违反即返工）

### 3.1 代码

| ❌ 禁止 | ✅ 允许 |
|---|---|
| 复制、粘贴、改写原模组任何 `.java` 文件 | 自己从零写代码 |
| 反编译 `.class`/`.jar` 后据其重写 | 读 **NeoForge / Minecraft 官方源码**（这是正当参考） |
| 沿用其类名、方法名、包名结构（如 `net.mrbt0907.*`） | 用自己的包名 `com.titanreborn.*` |
| 沿用其 `modid`（`thetitans`）、依赖库名（`mrbtutil`） | 用 `titanreborn` |

### 3.2 素材

| ❌ 禁止 | ✅ 允许 |
|---|---|
| 使用原模组的贴图（`.png`）、音效（`.ogg`）、模型（`.json`） | 自绘、自制、或使用**明确授权**的第三方素材 |
| 使用其语言文件文本（`en_US.lang` / `zh_CN.lang`） | 自己撰写文案 |
| 照搬其视觉设计（如五色长袍的**具体配色方案**） | 自建配色体系（"颜色代表职责"这个**思路**可用） |

> 已由内容组确认：原模组用紫/青/绿/红长袍区分职责，**具体配色不得沿用**，我们要自建配色。

### 3.3 命名裁定规则（比"禁用清单"更好用）

**核心规则：单个通用词可用；与原模组一致的名词组合必须避让。**

| 情况 | 裁定 | 例 |
|---|---|---|
| 通用题材词 | ✅ **可用** | "泰坦""泰坦生物""矿""祭坛""牧师" |
| 通用机制词 | ✅ **可用** | "重生长""破防""困难模式""噩梦"（作为概念描述） |
| 描述性功能位 | ✅ **可用**（用于讨论），但**落地命名需自建** | "生长血清"这个**概念**可讨论；我们的物品叫**催生灵液**（`quickening_ichor`） |
| 具体专名 | ❌ **禁用** | "创世之刃""完美之斧""末晶弓""凋灵斯拉""执行之龙""虚空之地" |
| 与原模组完全一致的名词组合 | ❌ **禁用** | 见下表 |

**已确认需避让的具体专名（发现一个补一个）：**

| 类别 | 禁用名 | 我们的替代 |
|---|---|---|
| 武器 | 创世之刃 / 完美之斧 / 末晶弓（哈肯典姆弓） | 虚寂之刃 / 裂骨战锤 / 拾荒重弩 |
| 道具 | 生长血清 | **催生灵液**（`quickening_ichor`） |
| 生物 | 凋灵斯拉 / 执行之龙 / 欧米伽虫 / 末影巨人 / 终极铁傀儡泰坦 / 雪傀儡泰坦 | 见 [10-content-roster.md](10-content-roster.md) |
| 地名 | 虚空之地 / 泰坦圣堂 | 待定名 |
| 模式 | 噩梦模式 / 灭神模式（作为**专名**） | 暂用"**困难模式**"，专名待定 |

> **落地口径（重要）**：文档里为便于讨论可以写"这个概念相当于原模组的噩梦模式"，
> 但**代码、语言文件、配置项里不得出现这些专名**。命名以 [10-content-roster.md](10-content-roster.md) 为准。

### 3.4 五级称谓的裁定

"忠诚者 / 牧师 / 狂热者 / 主教 / 圣骑士"是**通用宗教等级词**，单独看不受保护；
但**这五个词凑成一套与原模组官方译名完全一致的体系**，组合使用会引起混淆。

**裁定：中文显示名自建，英文注册名已自建。**

| 级别 | 英文注册名（已定） | 中文显示名（建议） |
|---|---|---|
| 1 | `devotee` | 信徒 |
| 2 | `chaplain` | 司祭 |
| 3 | `zealot` | 狂信者 |
| 4 | `hierarch` | 主祭 |
| 5 | `paladin` | 圣殿骑士 |

> 说明：英文 `zealot`/`paladin` 是英语通用词，风险低；中文避开"忠诚者/牧师/狂热者/主教/圣骑士"这套组合即可。
> 若后续取得作者授权，可再评估是否使用直译。

## 四、净室流程（怎么证明我们干净）

**核心要求：读"玩法描述"的人，和写代码的人，不共享代码知识。**

单人做这件事时的等效纪律：

1. **只从"玩法层"资料提取信息**：中文资料页（[mcmod 泰坦生物](https://www.mcmod.cn/class/628.html)）、视频、玩家讨论。
2. **不读原模组的 `.java` 文件**。原仓库源码已下载到 `.tmp\titans-src\`，**它只用于两件事**：
   - 核实"发行版有哪些内容"（看资源文件名清单，不看代码逻辑）；
   - 避免重名（比对物品/实体名清单）。
3. **凡是从玩法资料得出的结论，写进文档时标注来源**（见 [01-requirements.md](01-requirements.md) 的还原清单）。
4. **代码全部自己写**，遇到"不知道 1.21.1 怎么写"时，查 NeoForge/Minecraft 源码，**不查原模组源码**。

> 这条纪律的实际执行证据：`10-content-roster.md` 的撰写者明确记录"未读取 `.tmp/titans-src/` 下任何 `.java` 文件"。

## 五、发布前的合规检查表

发布（哪怕只是发到论坛/群）之前逐项确认：

- [ ] 仓库内**没有**原模组的任何文件（代码/贴图/音效/模型/语言文件）
- [ ] `modid` 与包名**不是** `thetitans` / `net.mrbt0907.*`
- [ ] 物品、实体、地名**没有**与第四节禁用清单重合的名称
- [ ] 贴图与音效**有自己来源的说明**（自绘 / 授权素材 / 明确许可的公共素材）
- [ ] README 中**明确致谢**原模组《泰坦生物》(The Titans) 及其作者，并声明"本模组为独立的玩法致敬作品，未使用其任何代码与素材"
- [ ] 若曾获得作者书面许可，把许可记录在 `docs/` 下（不建议公开原文，但要能证明）

## 六、待裁定的灰色地带

| # | 问题 | 现状 | 建议裁决 |
|---|---|---|---|
| 1 | 五级中文称谓"忠诚者/牧师/狂热者/主教/圣骑士" | 这些是**通用宗教等级词**，但与原模组官方中文译名组合一致 | 内容组已把**英文注册名**改为自建词根（devotee / chaplain / zealot / hierarch / paladin）。**中文显示名建议也自建**（如"信徒/司祭/狂信者/主祭/圣殿骑士"），彻底避开 |

## 七、与竞品的关系

1.21.1 生态里有两个同类作品，**都是 All Rights Reserved**：

| 竞品 | 授权 | 是否可参考其代码 |
|---|---|---|
| [TheTitansNeo](https://modrinth.com/mod/thetitansneo)（Aqua3，1.21/1.21.1，18.2 万下载） | ARR，仓库无 LICENSE（已实测确认） | ❌ **不可**。其仓库虽公开，但"公开可见"≠"授权使用" |
| [Neo The Titans](https://modrinth.com/mod/neo-the-titans)（Unknown54731，1.21.4，93.7 万下载） | ARR，无公开仓库 | ❌ 不可，且无法获取源码 |

**我们对它们的关系是并列竞争，不是衍生**：

- ❌ 不读其 `.java`（即使 TheTitansNeo 的源码可下载）
- ❌ 不反编译其 jar
- ❌ 不使用其贴图与音效
- ✅ 可以看**公开发布页的描述、截图、版本信息**来做竞品分析（这是正当的市场调研）
- ✅ 可以统计其**资源文件数量**来判断内容覆盖度（不读代码逻辑）

> 实操记录：分析 TheTitansNeo 时，我们只读取了 `neoforge.mods.toml`、`README.md`、
> 以及**文件类型与数量统计**，**未打开任何 `.java` 文件**。

> **一个值得注意的现象**：TheTitansNeo 自称是 "unofficial remaster" 原版闭源模组，
> 在未取得授权的情况下公开发布并已获 18 万下载。这**不构成我们可以照做的理由**——
> 别人未被追究不等于行为合法。我们的净室路线是主动选择，不是被迫妥协。
