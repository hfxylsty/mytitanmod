# 03 · 核心玩法系统设计

> 本文件职责：定义本模组的五大标志性玩法系统。这是**产品骨架**，也是与竞品的差异点。
> 所有机制描述只涉及"玩法思想"，不涉及任何原模组代码与素材。

## 〇、系统总览

```
                    ┌─────────────────┐
                    │   泰坦生成系统   │  ← 入口：泰坦怎么出现
                    └────────┬────────┘
                             ▼
        ┌────────────────────────────────────────┐
        │             泰坦实体（BOSS）             │
        │  ┌──────────┐ ┌──────────┐ ┌────────┐  │
        │  │  破防系统 │ │ 重生长系统│ │伤害规则│  │
        │  └──────────┘ └──────────┘ └────────┘  │
        └───────────────┬────────────────────────┘
                        ▼
              ┌───────────────────┐
              │  召唤物五级谱系    │  ← 泰坦的"教会"
              └───────────────────┘
                        ▲
              ┌───────────────────┐
              │   模式系统（双模）  │  ← 改变全局参数
              └───────────────────┘
```

五大系统的设计目标：**让"打泰坦"成为一场有阶段、有解谜、有爆发窗口的战斗**，而不是纯粹堆数值。

## 一、伤害规则系统

这是所有其他系统的基础。设计原则：**泰坦不是"血厚的怪"，而是"规则不同的存在"**。

### 1.1 伤害管线

1.21.1 的伤害修改入口是 `LivingIncomingDamageEvent`（可取消），已核验签名：

```java
public class LivingIncomingDamageEvent extends LivingEvent implements ICancellableEvent {
    public DamageSource getSource();
    public float getAmount();
    public float getOriginalAmount();
    public void setAmount(float newDamage);
    public void addReductionModifier(DamageContainer.Reduction type, IReductionFunction reductionFunc);
    public void setInvulnerabilityTicks(int ticks);
}
```

**处理顺序（我们的规则）**：

```
原始伤害
  ├─ 1. 目标非泰坦 → 不处理，走原版
  └─ 2. 目标是泰坦：
       ├─ 2.1 来源是作弊/创造模式？        → 特殊处理（见 1.4）
       ├─ 2.2 是否处于「重生长」无敌窗口？  → 免疫，伤害归零
       ├─ 2.3 是否满足「破防条件」？
       │      否 → 伤害归零（几乎免疫）
       │      是 → 继续
       ├─ 2.4 单次伤害 < 最小值？          → 归零
       ├─ 2.5 单次伤害 > 上限？            → 截断到上限
       ├─ 2.6 是否窃魂伤害？               → 无视护甲，走独立倍率
       └─ 2.7 应用难度/模式倍率
```

### 1.2 规则参数（设计值，待平衡）

| 规则 | 设计值 | 说明 |
|---|---|---|
| 单次伤害上限 | 1000（普通）/ 500（噩梦） | 强制"打得久"而非"一击秒" |
| 伤害冷却 | 1.5 秒 | 原版无敌帧不够，需用 `setInvulnerabilityTicks` 拉长 |
| 最小有效伤害 | 20 | 低于此值的攻击完全无效 |
| 击退抗性 | 1.0 | 泰坦不被击退 |
| 免疫伤害类型 | 燃烧 / 窒息 / 摔落 / 虚空 / 溺水 | |
| 免疫情形 | 时间流逝 / 和平难度 / 区块卸载 | 不自然消失 |
| 护甲值（分档） | 小型 21 / 普通 22 / 大型 23 / 神 24 | 非破防伤害几乎无效 |
| 重置条件 | 区块刷新、玩家退出重进 → 重置血量与仇恨 | 便于测试，也提高压力 |

### 1.3 窃魂伤害（Soul Steal）

一类**无视护甲**的特殊伤害，按难度缩放：

| 难度 | 倍率 |
|---|---|
| 简单 | ×0.5 |
| 普通 | ×1.0 |
| 困难 | ×2.0 |

用于：泰坦攻击高护甲目标、攻击创造模式玩家、摧毁其他模组盔甲时的附加伤害。

> 实现上建议用**自定义 `DamageType`**（`data/titanreborn/damage_type/soul_steal.json`）+ 标签控制"无视护甲"。

### 1.4 反作弊与创造模式处理

原设计里泰坦会"识破"创造模式玩家。我们的处理原则：**不踢人、不惩罚，但也不放行**。

| 情形 | 我们的处理 |
|---|---|
| 玩家处于创造模式 | 泰坦正常攻击，且该玩家的伤害对泰坦无效（可配置） |
| 玩家用 `/kill` 等指令 | 泰坦免疫指令击杀 |
| 玩家使用无敌类模组 | 泰坦伤害按"穿透无敌"计算（走独立伤害类型） |
| 和平难度 | 泰坦仍会攻击（可配置为"强制改为简单难度"） |

**明确不做**：把玩家踢出服务器。原设计有这条，但我们认为它破坏体验且有争议，改为"造成的伤害被记录并可在配置里开关惩罚"。

## 二、破防系统（Break / Stun）

### 2.1 为什么需要它

没有破防，战斗就是"站着对轰"。破防把每个泰坦变成**一道解谜题**：先弄清它的弱点，创造破防窗口，再打爆发。

### 2.2 状态机

```
   ┌─────────┐   满足破防条件    ┌─────────┐   窗口结束   ┌─────────┐
   │  未破防  │ ───────────────▶ │  破防中  │ ──────────▶ │  未破防  │
   │ 免疫伤害 │                  │ 可受伤   │             │ 免疫伤害 │
   └─────────┘                  └─────────┘             └─────────┘
        ▲                                                      │
        └──────────────────────────────────────────────────────┘
```

### 2.3 破防条件类型（可复用组件）

| 类型 | 说明 | 例子（我们自己的设计） |
|---|---|---|
| 射落附属物 | 泰坦身上挂若干目标物，全部击落后破防 | 会飞的水晶/眼 |
| 特定武器命中 | 必须用某类武器造成 N 次命中 | 某把弓 |
| 累积命中 | 命中特定部位 N 次 | 头部 |
| 环境触发 | 引入到特定地形/液体 | |
| 阶段触发 | 血量降到阈值后自动进入短暂破防 | 保底机制，避免无解 |

**设计约束**：每个泰坦必须有**至少一条保底的阶段破防**，否则玩家一旦弄不清条件就会卡死。

### 2.4 数据结构建议

用一个组件接口描述，便于复用：

```
BreakCondition（接口）
├── void onDamageTaken(TitanEntity titan, DamageSource src, float amount)
├── boolean isBroken(TitanEntity titan)
└── int breakWindowTicks()
```

每个泰坦在注册时声明一个 `List<BreakCondition>`。

## 三、重生长系统（Regrowth）

### 3.1 机制定义

泰坦血量低于阈值时，可能触发"缩小 → 免疫 → 重新长大"，**重置血量**。这是"防拖时间"的设计：玩家必须在窗口内打出足够爆发，否则前功尽弃。

### 3.2 触发条件（设计值，待平衡）

| 条件 | 值 |
|---|---|
| 触发血量 | < 5% |
| 每 tick 触发概率 | 1/1000 |
| 缩小时长 | 约 3 秒（缩到接近普通生物体型） |
| 无敌窗口 | 全程免疫外来伤害 |
| 结束时 | 血量重置为满血（或某个百分比，**待平衡**） |
| 冷却 | 触发后进入冷却，防止无限重生 |
| PvP 联动 | 两只泰坦互斗时，一方重生长且另一方血量 <50% → 另一方也触发 |

### 3.3 实现要点

- **体型变化用 `ModelPart` 缩放 + 碰撞箱调整**，不要换实体（换实体会丢状态、断 AI、触发区块问题）；
- 无敌窗口通过伤害管线里的状态检查实现，**不要**依赖原版无敌帧（原版最大无敌时间不够，且会被其他模组绕过）；
- 必须有冷却，否则低血量时频繁触发会变成"打不死"。

## 四、召唤物五级谱系

### 4.1 设计思想

原版泰坦最有趣的设计不是泰坦本身，而是它带着一整套**有职能分工的仆从体系**（像一个教会：信徒、祭司、狂信徒、主教、圣骑士）。我们的差异化重点就在这里。

### 4.2 五级职能表

| 等级 | 中文 | 英文 | 职能 | 关键特征 |
|---|---|---|---|---|
| 1 | 忠诚者 | Loyalist | 主力杂兵 | 攻击泰坦当前目标；数量最多 |
| 2 | 牧师 | Priest | 治疗 | 治疗附近受伤友军；自身脆弱 |
| 3 | 狂热者 | Zealot | 突进 | 跑得快、跳得高、闪避、可击杀更大体型目标 |
| 4 | 主教 | Bishop | 控场 | 施加"审判之雷"类减益；召唤下级；免疫火焰 |
| 5 | 圣骑士 | Paladin | 精英 | 飞行；免疫火焰与中毒；极高减伤；有普通/特殊两套攻击模式，可切换；**死亡时把增益回传给对应泰坦**（治疗它） |

### 4.3 生成上限（设计值，待平衡）

| 等级 | 上限 |
|---|---|
| 忠诚者 | 120 |
| 牧师 | 60 |
| 狂热者 | 30 |
| 主教 | 15 |
| 圣骑士 | 6 |

**实现约束**：上限必须**全局计数**（按泰坦实例统计），超限时不再生成。这是性能红线，见 [02-architecture.md](02-architecture.md) 第七节。

### 4.4 通用模板 + 泰坦变体

不为每个泰坦写五套召唤物，而是：

```
AbstractTitanMinion（通用 AI 与行为）
    ▲
    ├── MinionLoyalist    ← 通用实现，靠"所属泰坦"决定外观与数值
    ├── MinionPriest
    ├── MinionZealot
    ├── MinionBishop
    └── MinionPaladin
```

变体化通过**数据表**（每个泰坦一份：贴图前缀、血量/攻击倍率、专属增益），而不是子类爆炸。

### 4.5 AI 要点

- 召唤物**服从对应泰坦**：目标继承（忠诚者攻击泰坦所攻击的目标）；
- 泰坦死亡 → 召唤物进入"溃散"状态（推荐：逐渐消失或转为被动），避免残留实体堆积；
- 召唤物对泰坦的"回传"（圣骑士）必须**限流**，否则 6 个圣骑士同时死亡会瞬间回满血。

## 五、模式系统（双模式）

### 5.1 两种模式

| 模式 | 中文名 | 定位 | 核心改动 |
|---|---|---|---|
| 普通 | 普通模式 | 标准体验 | 伤害上限 1000 |
| 困难 | **噩梦模式** | 硬核挑战 | 伤害上限 500；泰坦行为更激进；召唤物上限提高 |

> 原版还有一个"灭神模式"。我们**先做两种**，第三种留到 M3 再评估——避免一开始就分叉太多。

### 5.2 模式如何生效

模式是**全局状态**，存在世界数据（`SavedData`）里，随存档持久化。通过配置项 + 指令切换。

**必须做**：模式切换时对所有已加载泰坦重新应用参数（不能只影响新生成的）。

## 六、泰坦生成系统

### 6.1 生成途径（四条，对应不同玩法节奏）

| 途径 | 说明 | 我们的设计 |
|---|---|---|
| 自然生成 | 随机稀有生成 | 概率**设计值 1/5000**（原版为 1/2000~1/25000，我们取中间值，待平衡），生成数量随已加载区块数增加 |
| 圣骑士转化 | 特定生物接触特殊力量后升格 | M2 |
| 灵魂附身 | 特殊道具附身对应生物 | M2 |
| 玩家召唤 | 用道具主动召唤（可控性最高） | **M1 必须有**，便于测试与演出 |

### 6.2 生成限制（防失控）

- 同维度同时存在的泰坦数量上限（建议 ≤4）；
- 生成位置必须离玩家有最小距离，避免"贴脸刷"；
- 泰坦不因区块卸载而消失，但**卸载期间不 tick**（性能）；
- 仇恨连锁：攻击一个泰坦会引来附近同类（保留这个经典设计）。

## 七、系统间的耦合与实现顺序

**依赖关系（决定开发顺序）**：

```
伤害规则系统  ──基础，必须先做
      │
      ├──▶ 破防系统
      │
      ├──▶ 重生长系统
      │
      └──▶ 召唤物谱系（依赖伤害规则做减伤）
                 │
                 └──▶ 模式系统（给上面全部加参数层）
                            │
                            └──▶ 生成系统（最后，避免早期被刷屏干扰测试）
```

**M1（垂直切片）只做**：伤害规则的最小版 + 一个破防条件 + 一个泰坦 + 一级召唤物 + 玩家召唤道具。
