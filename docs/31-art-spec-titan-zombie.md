# 31 · 僵尸泰坦 美术制作规格（Blockbench）

> 本文件职责：给做模型/贴图/动画的人（或你自己用 Blockbench）一份**精确规格**，
> 保证产出能直接被代码接上，不需要改 Java。
>
> **尺寸是硬约束**：32 格高 × 8 格宽（≈16 倍僵尸），与碰撞箱 `sized(8.0F, 32.0F)` 严格对应。
> 单位换算：**1 格 = 16 像素** → 模型 **512 像素高 × 128 像素宽**。

## 一、外观设定（来自原版描述，逐条落地）

> 原版描述原文要点：*"一只手持巨型铁剑、被放大 16 倍并高清化的僵尸，高 32 格、宽 8 格。
> 周身散发橙黄色粒子效果，四肢存在明显的关节结构，躯体被分成三节，
> 低血量时会穿上一层包覆全身的亮绿色透明护甲。"*

| # | 特征 | 实现层 | 归属 |
|---|---|---|---|
| 1 | 16 倍高清僵尸 | 模型 + 贴图：按 16 倍比例重建（贴图 256×256 = 原版 64×64 的 16 倍） | 美术（本文件） |
| 2 | 高 32 格、宽 8 格 | 模型尺寸 + 碰撞箱 | ✅ 已定（代码 `sized(8.0F, 32.0F)`） |
| 3 | 手持巨型铁剑 | **手持物品**，不是模型的一部分 | 见 §五 |
| 4 | 周身橙黄色粒子 | 客户端粒子发射器（代码层，M2） | 见 §六 |
| 5 | 四肢有明显关节结构 | 模型：肢体分段 + 关节处深色带 | 本文件 §三 |
| 6 | 躯体分三节 | 模型：`torso_0` / `torso_1` / `torso_2` | 本文件 §二 |
| 7 | 低血量亮绿透明护甲 | **独立的护甲层模型**，血线触发 | 见 §七 |

## 二、Blockbench 设置

| 项 | 值 |
|---|---|
| 项目类型 | **Bedrock / 基岩版模型**（不是 Java 模型） |
| 模型类型 | **Entity（实体）** |
| 格式版本 | `1.12.0` |
| 模型标识符 | `geometry.titan_zombie` |
| 贴图尺寸 | **256 × 256**（原版僵尸 64×64 的 16 倍） |
| 坐标单位 | 像素，1 格 = 16 像素；**脚底在 Y = 0，头顶到 Y = 512** |

> ⚠️ 必须是 **Bedrock 实体模型**。Java 模型（`models/` 下那种）GeckoLib 不认。

## 三、骨骼清单（**名字是硬约束**）

| 骨骼名 | 父级 | 用途 | 必须 |
|---|---|---|---|
| `body` | 根 | 躯干/手臂/头/甲片的变换支点（**pivot 放骨盆 Y≈152**，不画方块） | ✅ |
| `head` | body | 头 | ✅（GeckoLib 靠它做头部朝向） |
| `torso_0` / `torso_1` / `torso_2` | body | **躯体三节**，自下而上 | ✅ |
| `right_arm` / `left_arm` | body | 双臂 | ✅ 动画用 |
| `right_leg` / `left_leg` | 根 | 双腿（不挂 body，避免躯干旋转影响着地） | ✅ 动画用 |
| **`bone_plate_0` / `bone_plate_1` / `bone_plate_2`** | body | 胸前 3 片腐骨甲片 | ✅ **名字一字不能差** |

**为什么甲片名字是硬约束**：破防逻辑是「打中这 3 个具名部件 → 破防」，
名字写在代码里（`TitanZombie` 的 `bone_plates`）。名字不对 = 看得见甲片但打不掉。

### 尺寸参考（像素；脚底 Y=0、头顶 Y=512）

| 骨骼 | X 范围 | Y 范围 | Z 范围 | 贴图 UV |
|---|---|---|---|---|
| `head` | -32 ~ 32 | 448 ~ 512 | -32 ~ 32 | 0, 64 |
| `torso_0`（下节） | -36 ~ 36 | 152 ~ 224 | -20 ~ 20 | 72, 0 |
| `torso_1`（中节） | -36 ~ 36 | 224 ~ 296 | -20 ~ 20 | 72, 72 |
| `torso_2`（上节） | -36 ~ 36 | 296 ~ 368 | -20 ~ 20 | 72, 144 |
| `bone_plate_0/1/2` | -32/-8/16 ~ 各自 +16 | 240 ~ 280 | 20 ~ 28 | 0, 136/184/232 |
| `right_arm` | -64 ~ -36 | 160 ~ 340 | -14 ~ 14 | 0, 176 |
| `left_arm` | 36 ~ 64 | 160 ~ 340 | -14 ~ 14 | 136, 144 |
| `right_leg` | -64 ~ -20 | 0 ~ 152 | -16 ~ 16 | 136, 72 |
| `left_leg` | 20 ~ 64 | 0 ~ 152 | -16 ~ 16 | 136, 0 |

**总包围盒 = 128 × 512 像素 = 8 × 32 格**（已用脚本核验）。
这组数值可直接用；也可以按你的美术感觉调，但**总高必须落在 512 像素、总宽不超过 128 像素**。

### 关节结构（特征 5）

"四肢存在明显的关节结构"落到模型上 = **每条肢体画成两段 + 关节处留出深色带或略微收窄**：

- 手臂：上臂（Y 250~340）+ 前臂（Y 160~250），交界处 Z 略收窄或贴图用深色带
- 腿：大腿（Y 80~152）+ 小腿（Y 0~80），同上

若要做得更精细，可以把每段拆成独立骨骼（`right_arm_upper` / `right_arm_lower`），
但**必须保留 `right_arm` / `right_leg` 这两个名字作为父骨骼**，否则动画要改代码。

## 四、动画（**三个名字必须逐字一致**）

在 Blockbench 的 **Animate** 标签页创建，导出 Bedrock 动画（`format_version: 1.8.0`）：

| 动画名 | 循环 | 用途 | 最低要求 |
|---|---|---|---|
| `animation.titan_zombie.idle` | 循环 | 待机 | 躯干/头部轻微起伏 |
| `animation.titan_zombie.walk` | 循环 | 行走 | 双腿前后摆、双臂反向摆 |
| `animation.titan_zombie.attack` | **不循环** | 攻击一次 | 持剑手臂大幅挥下 |

> 代码已按这三个名字注册：idle/walk 按「是否移动」自动切换，attack 由战斗逻辑 `triggerAnim` 触发。

## 五、手持巨型铁剑（特征 3）

**不要把剑烘进 geo 模型**。Minecraft 的惯例是武器作为「手持物品」单独渲染，好处是：
换武器不用重做模型；掉落时自然掉出剑；数值改动不碰模型。

实现方式（代码层，M2 接入）：
- 在 GeckoLib 渲染器上加一个手持物品层（`GeoRenderLayer`，用 `ItemInHandRenderer` 或
  `GeoItemRenderer` 的思路），把 `Items.IRON_SWORD` 按**放大倍率**画在右手骨骼上；
- 放大倍率由剑长决定：原版铁剑约 1 格，泰坦的剑要按比例放大到 **约 8~10 格**（≈128~160 像素）。

**规格**：剑柄握点在右手（骨骼 `right_arm`，手部约 Y=160 处）。

## 六、橙黄色粒子（特征 4）

**代码层实现**（M2），不占模型：
- 在实体 `tick()` 或客户端 `ClientTickEvent` 里按间隔生成粒子；
- 颜色：橙黄（建议 `0xFFA500` ~ `0xFFD700` 区间的自定义 `ParticleType`，
  或先用原版 `ParticleTypes.FLAME` / `LAVA` 占位）；
- 分布：沿模型包围盒（128 × 512 像素）随机点，密度适中（建议每 2~4 tick 一颗）。

**美术需要提供的**：如果要用自定义粒子，给一张 8×8 或 16×16 的粒子贴图（橙黄发光感）。

## 七、低血量亮绿透明护甲（特征 7）

**这是最有辨识度的特征，建议单独做一层模型。**

方案：做一个**独立的护甲层 geo 文件**（如 `titan_zombie_armor.geo.json`），
骨骼名与本体一致，但每个立方体**比本体大 2~4 像素**（包覆感），贴图用**亮绿 + 半透明**。

| 项 | 规格 |
|---|---|
| 文件 | `assets/titanreborn/geo/entity/titan_zombie_armor.geo.json` |
| 骨骼名 | 与本体一致（`head` / `torso_*` / `*_arm` / `*_leg`），便于同步动画 |
| 尺寸 | 每根骨骼的立方体比本体外扩 2~4 像素 |
| 贴图 | `textures/entity/titan_zombie_armor.png`，**亮绿**（如 `0x55FF55` 系），alpha 建议 120~160（半透明） |
| 触发 | 血量低于阈值时由渲染器决定是否叠加渲染（代码层，M2） |
| 附片甲 | **不需要**给 `bone_plate_*` 做护甲——甲片被打碎是破防机制，与护甲层无关 |

> 如果嫌做第二层模型麻烦，**退路**是在本体贴图里预留"亮绿护甲"区域，
> 低血量时切换到另一张贴图（`withAltTexture`）。但视觉上不如独立层"包覆"感强。

## 九、交付前自查清单

- [ ] 是 **Bedrock 实体模型**，格式 `1.12.0`，identifier `geometry.titan_zombie`
- [ ] **总高 512 像素（32 格）、总宽 ≤128 像素（8 格）** ← 最重要
- [ ] 骨骼名逐字一致，尤其 **`bone_plate_0/1/2`**
- [ ] 三个甲片是独立骨骼、位于正面胸口、投影面积不小于 16×40 像素（否则打不中）
- [ ] **躯体分三节**（`torso_0/1/2` 三个独立骨骼）
- [ ] **四肢有关节结构**（分两段 + 关节收窄/深色带）
- [ ] 三个动画名逐字一致，attack 不循环
- [ ] 贴图 UV 无重叠；甲片颜色明显区别于躯干
- [ ] 铁剑**没有**烘进模型（走手持物品）
- [ ] 文件名都是 `titan_zombie`
- [ ] 贴图自绘或授权素材，**非原模组素材**（见 [07-compliance.md](07-compliance.md)）

## 十、当前占位模型说明

仓库里现在是一份**程序生成的占位模型**（`MakeTitanAssets`），已经满足：

- ✅ 尺寸：512 × 128 像素 = 32 × 8 格
- ✅ 三节躯干、12 个骨骼、UV 不重叠、四肢分段
- ⚠️ 但外观是"方盒拼装"，没有关节细节、没有剑、没有护甲层——**等 Blockbench 正式模型替换**

替换时**只需覆盖那三个文件**，Java 代码不用动。
