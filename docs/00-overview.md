# 00 · 项目定位与边界

## 一、这是什么

一个面向 **Minecraft 1.21.1 + NeoForge** 的**原创模组**，题材是"巨型泰坦 BOSS 生存战"。

它借鉴《泰坦生物》(The Titans) 的**玩法与系统结构**，但**代码、美术、音效全部自建**。这不叫"移植"，叫**净室重实现（clean-room reimplementation）**。

> 为什么不做迁移、不做反编译，见 [PORT-PLAN.md](PORT-PLAN.md) 的完整论证。一句话版本：
> 公开源码只是骨架（覆盖发行版不到 1/8）、两个仓库都没有 LICENSE、资源层格式不兼容必须重做——
> 三条叠加后，"搬代码"这条路既不合规也不省事。

## 三、目标

### 3.1 差异化目标（本项目的存在理由）

1.21.x 上已有**两个**成熟竞品，且都是**内容移植**路线（详见 [01-requirements.md](01-requirements.md) 的竞品分析）：

| 竞品 | 版本 | 下载 | 做法 |
|---|---|---|---|
| [TheTitansNeo](https://modrinth.com/mod/thetitansneo)（Aqua3） | **1.21 / 1.21.1** | 18.2 万 | 自述 "unofficial remaster"；卖点是强力怪、武器工具盔甲、金/钻石食物 |
| [Neo The Titans](https://modrinth.com/mod/neo-the-titans)（Unknown54731） | 1.21.4 | 93.7 万 | 自述 "recreates and optimizes"；动画优化 + 数值平衡 + 加指令 |

**两者都在拼"内容量"：怪、武器、装备。没有任何一个把原版那套系统当作核心卖点。**

因此我们**不拼泰坦数量**，而是做两个竞品都没重点做的机制系统：

1. **召唤物五级谱系** —— 忠诚者 / 牧师 / 狂热者 / 主教 / 圣骑士，各有独立 AI 与职责，构成"泰坦的教会"式生态；
2. **重生长（Regrowth）机制** —— 低血量时缩小回普通体型再长大，重置血量并短暂免疫，逼玩家打爆发；
3. **破除条件（破防）系统** —— 每个泰坦有专属弱点条件（射落水晶、特定武器、击晕），未破防几乎免疫伤害；
4. **双模式** —— 普通模式 / 困难模式，改变伤害上限与泰坦行为；
5. **伤害规则体系** —— 窃魂伤害、护甲无视、创造模式特判等一整套"神性规则"。

**这五条是我们的产品骨架。** 泰坦数量可以少，但这五条必须做到。

**合规提示**：两个竞品**均为 All Rights Reserved 且无授权**（TheTitansNeo 有公开仓库但无 LICENSE，Neo The Titans 连仓库都没有）。
我们对它们的关系是**并列竞争，不是衍生**：不读其代码、不反编译其 jar、不使用其素材。见 [07-compliance.md](07-compliance.md) 第七节。

### 3.2 工程目标

- 1.21.1 + NeoForge，单一 modid，客户端/服务端都装；
- 数据驱动优先（配方、战利品、标签、维度、生物群系都用 JSON），Java 只写逻辑；
- 每个里程碑都有**可自动判定的验收标准**（见 [06-roadmap.md](06-roadmap.md)）；
- 构建可复现：`gradlew build` 一条命令，不依赖手工步骤。

## 四、非目标（明确不做，避免范围蔓延）

| 不做 | 原因 |
|---|---|
| 复刻原模组的全部 19 泰坦 / 222 物品 | 那是原团队多年工作量；我们做机制差异化，不做内容对等 |
| 使用原模组的贴图 / 音效 / 模型 / 语言文件 | 版权（见 [07-compliance.md](07-compliance.md)） |
| 反编译原模组 jar | 合规红线 |
| 支持 1.21.1 以外的版本 | 单版本聚焦；跨版本移植等玩法稳定后再说 |
| Fabric / Forge 双端 | 只做 NeoForge |
| 数据包 / 资源包形态 | 本模组是 Java 模组，不是数据包 |

| `ENVIRONMENT.md` | 环境与已知坑速查，保留在仓库根目录。 |
