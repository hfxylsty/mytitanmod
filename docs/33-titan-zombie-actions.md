# 33 · 僵尸泰坦动作与行为规格（逆向自原模组行为）

> 本文件职责：记录原模组**僵尸泰坦的动作集合与状态机规律**，作为我们实现的动作设计依据。
>
> **合规说明**：本文件只记录**行为事实与数值规律**（玩法机制属"思想"），
> **不包含也不搬运原模组源码**。实现一律由我们自己撰写。
> 依据来源：本地已下载的原模组 1.12.2 开发分支源码（行为分析），见 [07-compliance.md](07-compliance.md)。

## 一、最重要的结论：**它没有真正的状态机**

原模组的"动作"不是设计成 `IDLE / WALK / ATTACK / HURT` 这样的状态枚举，
而是**一组各自独立计数的整数计时器**，动画层读取这些数值来决定姿势：

| 计时器 / 标记 | 作用 | 生命周期 |
|---|---|---|
| `attackTimer` | 攻击动作进度 | 攻击命中时置 **20**，每 tick 减 1 |
| `invulTime` | 降生/重生的无敌期 | 置为 `50 × (变体+1) − 49`，每 tick 减 1 |
| `deathTicks` | 死亡演出进度 | 死亡时每 tick 加 1 |
| `hurtResistantTime` | 受击后的免伤窗口 | 置 **40**（= 2 秒） |
| `limbSwing / limbSwingAmount` | 行走摆动 | 由原版 `EntityLiving` 驱动 |

**动画的做法**：渲染器检查 `attackTimer > 0` → 摆出攻击姿势；`invulTime > 0` → 摆出降生姿势；
`deathTicks > 0` → 播放死亡演出。**没有状态之间的显式转移，只有"计时器是否大于 0"。**

> **对我们的启示**：这套做法能跑，但**表达力很弱**——无法表达"蓄力→挥砍→收势"这种
> 有阶段的重攻击，也无法表达"被打断"。我们的 GeckoLib 方案天生支持多状态动画，
> **没必要模仿这种计时器风格**，但可以借鉴它"哪些时刻需要播动作"。

## 二、动作清单（共 6 类）

### 2.1 近战重击（主动攻击）

| 项 | 规律 |
|---|---|
| 触发 | 与目标的距离 ≤ `自身宽度 + 目标宽度 + 体型倍率 × 0.8` 时自动触发 |
| 冷却 | 受 `attackTimer ≤ 0` 约束 → **约 1 秒**（20 tick） |
| 动作 | 挥动主手（`swingArm`）→ `attackTimer = 20` |
| 伤害倍率 | 对**大型目标**（碰撞箱高 ≥ 8 格，或同样是泰坦）伤害 **×20**；普通目标 ×1 |
| 溅射 | 对身体周围 `体型倍率 × 0.25 + 1` 格内的**其他**实体造成 **25%** 伤害，并附带额外效果 |
| 同步 | 服务端置计时器后通过实体状态包（id=4）通知客户端，客户端同样置 20 |

> 那个 ×20 的判定值得注意：原模组用"目标是否够大"来决定伤害倍率，
> 效果是**泰坦打泰坦才会互相造成可观伤害**，打普通生物只用基础值。
> 我们已有类似的"泰坦减伤"规则，**这条要反过来也想清楚**（见 [03-gameplay-systems.md](03-gameplay-systems.md) §1）。

### 2.2 远程攻击

| 项 | 规律 |
|---|---|
| 触发 | 目标**不在**近战距离内时，每 tick 尝试 |
| 实现 | 接口为原版 `IRangedAttackMob`（即"会远程攻击的怪"） |
| 冷却 | 与近战共用同一个 `attackTimer` 门槛 |

> 僵尸泰坦作为近战原型，远程攻击在原型类里没有特别实现；
> 它是从基类继承的通用行为（骷髅类泰坦才真正用弓）。

### 2.3 跳跃扑击（追击高处/远处目标）

| 项 | 规律 |
|---|---|
| 触发条件 | 目标比自己高出 `自身高度 + 目标高度 + 4` 格，**或**距离 ≤ `宽度和 + 体型倍率`；且自身在地面 |
| 概率 | `rand.nextInt(200 − min(目标高度差, 190)) == 0` → 目标越高，触发概率越大 |
| 动作 | 起跳，并朝目标方向施加水平冲量，垂直速度随高度差增加 |
| 落地 | 见 2.4 |

### 2.4 落地冲击（砸地）

| 项 | 规律 |
|---|---|
| 触发 | 下落距离 > `体型倍率 × 2` 格 |
| 音效 | 爆炸音（音量随下落距离） |
| 伤害 | 周围 `体型倍率 × 2 + 下落距离` 格内实体，伤害约 `100 × 下落距离 − 距离 × 倍率` |
| 击退 | 强力击退（水平朝外 + 垂直上抛），并单独给远程玩家发速度同步包 |

> **这是巨兽手感的关键动作**：泰坦跳起来砸下去，周围全部掀飞。
> 我们的模型有 `right_leg_lower` / `left_leg_lower` 关节，**很适合做落地屈膝动画**。

### 2.5 降生 / 重生（无敌 + 缩放演出）

| 项 | 规律 |
|---|---|
| 触发 | 生成时（`ignite`）、以及**吞噬同类后升阶**时 |
| 无敌时长 | `50 × (变体 + 1) − 49` tick（变体 0 → 1 tick；变体 63 → 3149 tick） |
| 体型联动 | 无敌期间**逐渐缩小**：`体型 − 无敌剩余 × 0.02`，下限 1 |
| 视觉 | 每 tick 生成爆炸粒子（按体型选 `EXPLOSION_HUGE/LARGE/NORMAL`）+ 火花粒子 |
| 状态冻结 | 无敌期间**冻结移动**（速度归零）、`limbSwing` 归零、`hurtResistantTime = 40`、`ticksExisted` 被重置到 10 |
| 音效 | 播放 `titan.birth` |

> 注意"**无敌期间体型逐渐缩小**"——这就是**重生长（Regrowth）的原始实现**。
> 我们 [03-gameplay-systems.md](03-gameplay-systems.md) §3 设计的"缩小→无敌→长回去"正是从这里来的，
> 但原版只是"期间一直在缩小"，**没有"再长回去"的过程**（无敌结束后体型直接按倍率恢复）。
> 我们可以做得更好：**缩到最小 → 停一下 → 逐帧长回去**。

### 2.6 死亡演出

| 项 | 规律 |
|---|---|
| 计数 | `deathTicks` 每 tick 加 1 |
| 体型 | `deathTicks > 100` 后**高度塌缩到 0.1 格**（倒地/塌陷） |
| 持续 | 死亡动画期间继续走 `onDeathUpdate`，直到演出结束 |

### 2.7 附加行为：踩踏小生物

基类里有一条：**比自己矮一半以上的非 BOSS 实体，只要碰撞箱与自己相交，就会被持续伤害**。
——泰坦站在那里不动，脚下的小怪就会被踩死。

## 三、数值规律（变体系统）

原模组用一个 **`variant`（变体）整数 0 ~ 63+** 驱动**全部数值**，这是它最核心的设计：

| 项 | 公式 |
|---|---|
| 体型倍率 | `variant + 1`（无敌期间还会按 2.5 递减） |
| 生命值 | `7000 × 体型倍率`，再按变体阈值连乘：`≥7 ×2`、`≥15 ×2`、`≥31 ×5`、`≥63 ×10` |
| 攻击力 | `70 × 体型倍率`，同样的阈值连乘 |
| 移动速度 | `0.75 − 体型倍率 × 0.05`，下限 0.25 |
| **狂暴** | 血量 ≤ 50% → 速度 **×2**；血量 ≤ 25% → **再 ×2** |
| 击退抗性 | **1.0**（完全免疫击退） |
| 摔落免疫 | 是（但有 2.4 的落地冲击） |
| 火焰免疫 | 是 |
| 掉落下界/虚空 | 会被钳制在 Y=0 与 Y=300 之间（不会掉出世界） |
| 经验值 | 3000 |

**吞噬升阶**：杀死**同类的低阶泰坦**后，自己的 `variant` 增加对方的变体数 +1，
并**触发一次降生无敌演出**（2.5）——即"越打越强、每次升阶都要重新破防"。

**变体 ≥63 的特殊行为**：周围实体有 `1/3000` 概率被真实闪电劈中（500 伤害），
并且自身周围随机落雷。

**变体影响音效**：体型 ≤7 时用原版僵尸音效；>7 时换成自定义的泰坦音效
（`titan.zombie.living` / `.grunt` / `.death` / `titan.step`）。

## 四、对我们的落地建议

| 原模组做法 | 我们的做法 | 理由 |
|---|---|---|
| 计时器驱动、无状态机 | **用 GeckoLib 动画控制器做真状态机** | 支持"蓄力→挥砍→收势"、支持被打断 |
| 只有 3 个笼统动作 | **动作集扩充到 8~10 个**（见下） | 我们的模型有完整关节骨架，浪费可惜 |
| 无敌期持续缩小 | **缩小 → 停顿 → 长回** 三阶段 | 视觉更清楚，也给了玩家"还有机会"的信息 |
| 变体系统驱动全部数值 | **保留这个思路** | 它很优雅：一个整数就能做大范围难度分层 |
| 落地冲击 | **沿用，并配屈膝动画** | 巨兽手感的关键 |
| 踩踏小生物 | 沿用 | 符合"神性存在"的设定 |

### 建议的动作集（M1 先做前 3 个）

| # | 动作 | 状态机中的位置 | 优先级 |
|---|---|---|---|
| 1 | `idle` | 无目标 / 待机 | M1 |
| 2 | `walk` | 移动中 | M1 |
| 3 | `attack` | 近战重击（蓄力→挥砍→收势） | M1 |
| 4 | `jump_smash` | 扑击起跳 + 落地砸地 | M2 |
| 5 | `hurt` | 受击 | M2 |
| 6 | `roar` | 召唤小弟 / 进入新阶段 | M2 |
| 7 | `regrow_shrink` | 重生长·缩小 | M2 |
| 8 | `regrow_grow` | 重生长·长回 | M2 |
| 9 | `armor_on` | 低血量护甲浮现 | M3 |
| 10 | `death` | 死亡塌缩 | M3 |

> 我们的 Blockbench 工程目前只有 `idle / walk / attack` 三个动画
> （见 [31-art-spec-titan-zombie.md](31-art-spec-titan-zombie.md)）。
> 后续要用 `.bbmodel` 工程在 Blockbench 里补做 4~10。
