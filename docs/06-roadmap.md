# 06 · 路线图与验收标准

> 本文件职责：定义每个里程碑**做什么、做到什么算完成**。
> 原则：**每个里程碑都必须有可自动判定的验收标准**，不接受"感觉差不多了"。

## 一、里程碑总览

| 里程碑 | 目标 | 估计量级 | 状态 |
|---|---|---|---|
| **M0** 技术验证 | 四项未知技术各自跑通最小实验 | 3~5 天 | 🚧 进行中（0.1/0.2/0.3/0.5 已落地；0.4 未做。详见 [30-m0-verification.md](30-m0-verification.md)） |
| **M1** 垂直切片 | 1 个泰坦 + 1 级召唤物 + 破防 + 重生长 + 渲染，端到端可玩 | 2~4 周 | ⬜ |
| **M2** 核心玩法完备 | 4~5 个泰坦、五级召唤物、双模式、生成系统 | 1~2 个月 | ⬜ |
| **M3** 内容与差异化 | 维度、装备体系、更多泰坦、指令与配置完善 | 3~6 个月 | ⬜ |
| **M4** 打磨与发布 | 平衡、性能、多人测试、合规检查 | 1~2 个月 | ⬜ |

> 量级是**粗估**，M0 结束后用实测数据校准 M1。原模组的发行版规模（19 泰坦 / 222 物品）是原团队多年工作量，**不在我们的目标范围内**（见 [00-overview.md](00-overview.md) 非目标）。

## 二、M0 · 技术验证（先做实验，再写功能）

**目的**：把四个"不知道能不能行"的问题各自用最小实验回答。**实验代码可以直接丢弃**，只留结论写回文档。

| # | 实验 | 通过标准 | 若不通过 |
|---|---|---|---|
| 0.1 | 建 `titanreborn/` 工程（ModDevGradle + JS 21 + NeoForge 21.1.x） | `gradlew build` → `BUILD SUCCESSFUL` | 照 `example-mod/` 复制配置（已验证可跑） |
| 0.2 | 注册一个自定义实体 + 属性 + 渲染器，能刷出来 | `runClient` 进世界用刷怪蛋生成，实体可见会动 | 排查注册链路四步（见 [02-architecture.md](02-architecture.md) 2.3） |
| 0.3 | **多部件**：一个 `PartEntity` 子类，攻击部件能转发伤害给宿主 | 日志打出"命中部件 X → 宿主受伤" | 退路：逻辑多部件（单碰撞箱 + 按坐标判定部位） |
| 0.4 | **GeckoLib** 依赖接入 + 一个缩放模型 | `gradlew build` 通过，`runClient` 看到模型 | 退路：纯原版 `ModelPart` 手写动画 |
| 0.5 | 自定义伤害事件改伤害 | 打在泰坦身上伤害被改（日志/血量可观测） | 排查事件总线（`LivingIncomingDamageEvent` 是游戏总线） |

**M0 验收**：五项全部有结论（通过或明确退路），且结论**写回对应文档**（把"待验证"改成实测定论）。

> M0 的价值：把风险前置。**这五项里有任何一项没结论，就不要进 M1。**

## 三、M1 · 垂直切片

### 3.1 范围（只做这些，其余一律不做）

**选定的泰坦**：**僵尸泰坦 / Zombie Titan**（原型僵尸，8× 体型）——理由见 [10-content-roster.md](10-content-roster.md)：原型 AI 最简单，但能一次验证整条链路。

| 模块 | M1 做什么 |
|---|---|
| 实体 | 1 个泰坦（`AbstractTitan` 基类 + 1 个子类），四步注册链路完整 |
| 多部件 | 头 / 胸 / 3 片腐骨甲片，共 5 个部件 |
| 破防 | **1 种**：击碎 3 片腐骨甲片 → 8 秒破防窗口；外加**保底的阶段破防**（血量阈值自动触发） |
| 重生长 | 完整实现触发、缩小、无敌、重置、冷却 |
| 伤害规则 | 最小版：破防检查 + 伤害上限 + 最小伤害门槛 + 免疫列表 |
| 召唤物 | **只做一级（忠诚者）**，通用 AI + 该泰坦的变体数值 |
| 物品 | 1 个召唤道具（玩家主动召唤，便于测试） |
| 渲染 | GeckoLib 模型 + 缩放，与碰撞箱对齐 |
| 数据 | 掉落表、配方（召唤道具）、标签各 1 份 |
| 客户端 | 血条显示（可用原版），不做自定义 GUI |

**M1 明确不做**：其他泰坦、二~五级召唤物、双模式、维度、自然生成、指令系统、装备体系。

### 3.2 验收标准（可自动判定）

| # | 验收项 | 判定方式 | 判定人 |
|---|---|---|---|
| A1 | 构建通过 | `gradlew build` 输出 `BUILD SUCCESSFUL`，产物 jar 存在 | 自动 |
| A2 | 客户端启动 | `gradlew runClient` 进主菜单，日志无致命错误，日志出现 `mod/titanreborn` | 自动 |
| A3 | 模组加载 | 日志出现 mod 名与版本行 | 自动 |
| A4 | 实体可生成 | `/summon titanreborn:titan_zombie` 成功，实体可见、会动、有碰撞箱 | 自动+目视 |
| A5 | 多部件命中 | 攻击不同部位，日志/行为区分部位名 | 自动 |
| A6 | 破防生效 | 未破防时攻击伤害≈0；击碎 3 片甲片后同一攻击造成实伤 | 自动 |
| A7 | 重生长触发 | 血量降至阈值以下，可观测定时触发缩小→无敌→恢复 | 自动 |
| A8 | 免疫生效 | 火焰/摔落/虚空伤害对泰坦无效 | 自动 |
| A9 | 召唤物 | 使用召唤道具生成忠诚者，它会攻击玩家（继承泰坦目标） | 自动+目视 |
| A10 | 数据生效 | 击杀泰坦掉落掉落表物品；召唤道具可用配方合成 | 自动 |
| A11 | 专用服务器 | `runServer` 能启动且不崩（客户端类没被误加载） | 自动 |

> A1~A3、A11 可完全脚本化；A4~A10 需要 `runClient` + 人工操作，但**状态可用日志断言**。
> **建议**：M1 结束时把这套跑一遍并记录日志片段到 `docs/` 下作为证据。

### 3.3 M1 完成后的产出

1. 可运行的泰坦模组（1 个泰坦可战）；
2. 把 M0/M1 趟通的 **实体注册、多部件、GeckoLib、伤害事件**四个主题**回写成技能文档**（补 `minecraft-modding` 技能缺的实体/客户端/网络三篇）；
3. 校准 M2 的工期估计。

## 四、M2 · 核心玩法完备（差异化兑现）

| 模块 | 内容 |
|---|---|
| 泰坦 | 增至 4~5 个（见 `10-content-roster.md` 的 M2 档），覆盖不同原型与不同破防条件 |
| 召唤物 | **五级谱系全部实现**：忠诚者 / 牧师 / 狂热者 / 主教 / 圣骑士，含各自职能 AI |
| 模式系统 | 普通 / 噩梦双模式，全局参数层，切换时重算已加载泰坦 |
| 伤害规则 | 完整版：窃魂伤害（自定义 `damage_type`）、护甲无视、创造模式处理、仇恨连锁 |
| 生成系统 | 自然生成（含稀有度与数量限制）、玩家召唤；**暂不做**灵魂附身/圣骑士转化 |
| 性能 | 召唤物上限全局计数；距离降频；压测出 TPS/帧率数据 |

**M2 验收**：五级召唤物各自的职能可观测（牧师会治疗、主教会上减益、圣骑士死亡回传治疗泰坦）；
双模式切换后参数实际变化；同时 4 个泰坦 + 满载召唤物时 TPS ≥ 18（设计值，实测校准）。

## 五、M3 · 内容与差异化扩展

- 维度与维度战（数据驱动 `data/titanreborn/dimension/`）；
- 泰坦材质装备线与破防武器（内容组已给原创命名）；
- 剩余召唤物变体；
- 指令系统（如 `/titanreborn mode`）；
- 配置项完善；
- 第三个模式（"灭神"级难度）——**评估后决定是否做**。

## 六、M4 · 打磨与发布

- 数值平衡（拿实测数据调，不拍脑袋）；
- 性能优化（巨型实体渲染、召唤物 AI 开销）；
- 多人联机与专用服务器完整测试；
- 兼容性测试（与常见优化模组、JEI 等共存）；
- **执行 [07-compliance.md](07-compliance.md) 第五节发布前检查表**；
- 撰写 README（含向原模组致谢）。

## 七、关键风险登记表

| # | 风险 | 影响 | 应对 | 触发时机 |
|---|---|---|---|---|
| R1 | GeckoLib 接入失败或观感不佳 | 渲染方案推翻 | M0 实验 0.4 提前暴露；退路为原版模型 | M0 |
| R2 | 多部件机制不满足需求（如需要部件独立受伤/破坏） | 破防设计受限 | M0 实验 0.3；退路为逻辑多部件 | M0 |
| R3 | 巨型实体性能炸裂（多部件 AABB + AI） | 不可玩 | M1 起就压测；部件数 ≤8；限制同屏泰坦数 | M1 |
| R4 | 范围蔓延（想加更多泰坦/物品） | 永远做不完 | 严格执行"非目标"清单；M1 明确不做项 | 全程 |
| R5 | 合规风险（名称/素材撞车） | 无法发布 | 命名清单 + 发布前检查表；建议取得作者授权 | 发布前 |
| R6 | 与已有竞品同质化 | 做完没人玩 | 坚持五条差异化（[00-overview.md](00-overview.md) 3.1） | M2 |
| R7 | 技能文档缺口（实体/客户端/网络未覆盖） | 开发变慢、易踩坑 | M1 结束回写技能文档 | M1 后 |
